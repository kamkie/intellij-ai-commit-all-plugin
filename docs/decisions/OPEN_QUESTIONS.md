# Open Questions

This file tracks unresolved user input that blocks an ADR, plan, proposal finding, task, implementation branch, or release decision. It is an active register, not a historical log.

Keep implementation work in `TASKS.md`, plans, proposals, ADRs, or source files as appropriate.

## Active Questions

_No open questions._

## Editing Rules

- Use one row per unresolved question in `## Active Questions`.
- Assign IDs in `Q-<AREA>-NNN` form, for example `Q-UX-001`.
- When active questions exist, use this table shape:

| ID | Question | Blocks | Needed For | Updated |
|----|----------|--------|------------|---------|

- `Blocks` must link to at least one artifact that cannot proceed without the answer, such as an ADR, plan, proposal finding, task, implementation branch, release decision, or file.
- `Needed For` should state why the answer is required.
- Use `Updated` dates in `YYYY-MM-DD` form.
- When the answer lands, record it in the ADR, plan, proposal, task, or implementation artifact that uses it, then remove the row.
- If all rows are resolved, restore `_No open questions._`.
